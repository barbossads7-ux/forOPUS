# Уроки из Skimreel: удалённый MCP-коннектор для Claude

Источник: `DECISIONS.md` проекта Skimreel, «Шаг 2» и «Шаг 3» (2026-10-28). Здесь только то, что нужно для нового
MCP-сервера. Статусы честные: **проверено владельцем** = работало в claude.ai; **написано/тест** = только код и
офлайн-тесты; **не проверено** = неизвестно.

## Авторизация (OAuth 2.1)

- **Проверено владельцем (claude.ai, компьютер):** коннектор по общей ссылке `https://<домен>/mcp` подключается через
  OAuth. Домен-заглушка `sslip.io` с HTTPS claude.ai принимает — собственный домен для OAuth не нужен.
- **Как подключается claude.ai** (проверено по тесту с клиентом MCP SDK и вживую): сам регистрируется через `/register`
  (динамическая регистрация клиентов, должна быть открыта) → `/authorize` → страница входа → код → `/token` с PKCE S256.
- **Внимание, версия протокола (со слов новой сессии sitecraft, 2026-11-03, мной не проверено):** версия MCP от
  28 июля 2026 объявила регистрацию клиентов через `/register` устаревшей. Skimreel подключался к claude.ai именно
  так, поэтому на этапе 5 проверить заново, чем заменена регистрация и что поддерживает claude.ai.
- **Сервер без токена** отвечает 401 с адресом `resource_metadata`; нужны метаданные ресурса
  (`/.well-known/oauth-protected-resource`) и сервера (issuer, `/authorize`, `/token`, `/register`, S256).
- **Токены:** доступ — 1 час, refresh — 60 дней с ротацией (старый перестаёт работать), код — 5 минут и одноразовый.
  В базе только sha256-хэши. Токен привязан к адресу подключения (RFC 8707 `resource`): со старого домена на новый он
  не переносится, пользователю нужно подключиться заново.
- **Остаточные риски:** `/register` открыт для всех (мусорные клиенты возможны, лимит по IP на прокси); фишинг
  подтверждения входа (защита — текст и код сверки на экране подтверждения).
- **Для sitecraft-mcp:** у него «ключи или OAuth» стоят в этапе 5 (продажа). Здесь есть готовый проверенный путь
  OAuth; для ключей (без OAuth) поведение claude.ai — **не проверено**.
- Готовые обработчики дают официальные SDK; Skimreel использует Python SDK (`mcp.server.auth`). Для TypeScript
  сверить, что есть в актуальном SDK и в `mcp-handler`, не по памяти.

## Иконка коннектора в claude.ai

- **Источник — выводы из публичного issue** `github.com/anthropics/claude-ai-mcp/issues/152` (открыта, ответа Anthropic
  нет); сам в claude.ai не проверял: иконку берут не из `serverInfo.icons`, а из сервиса фавиконов Google по **двум
  последним частям домена**, по http. Для `sslip.io` будет чужой стандартный значок.
- **Проверено:** прозрачные углы фавикона в тёмной теме claude.ai заливаются белым → делать квадратный фавикон без
  прозрачности.
- Вывод: иконка требует своего домена (`mcp.<домен>` → `<домен>`), сайт на нём должен отдавать `/favicon.ico` и по http.
  Для sitecraft-mcp на Vercel домен `*.vercel.app` покажет чужой значок.

## Описания инструментов

- В описаниях стоит прямо писать «ловушки»: что считается новым запросом, что повторный вызов бесплатный, что лимит
  общий, как долго идёт долгий вызов. Claude иначе вызывает инструмент повторно или не понимает цену.
- Инструмент, который возвращает то, что Claude напишет сам, не нужен: в Skimreel контент-план не стали делать
  инструментом — Claude строит его сам по данным `analyze_channel`.
- Долгие операции в Skimreel сделаны фоновой задачей с ожиданием до 25 с и отдельным `job_status`: запас под таймауты
  клиентов (точное значение таймаута claude.ai **не проверено**). Статус: написано и проверено офлайн-тестами,
  **в живом Claude не проверено**; риск — Claude может не вызвать `job_status`. sitecraft-mcp долгих операций не
  планирует (инструменты быстрые), так что пока просто знать.

## Что не переносится

Бот, Mini App, SQLite, звёзды Telegram, yt-dlp, Gemini и OpenRouter, VPS. Модель sitecraft-mcp — без хранения данных
и без внешних API, поэтому ничего из этого ему не нужно.
